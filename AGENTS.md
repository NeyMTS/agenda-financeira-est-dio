- Administrative access uses `user_roles` plus fail-closed authenticated server functions; never infer admin status from email or client state, because URL and API access must remain server-authorized.
- Day agenda rows must include exact appointment and calendar-block start times; entries hidden by invalid or duplicate times must have recovery edit actions, so every existing entry remains editable without allowing conflicting saves.
- Birthday WhatsApp actions share one helper and the user's configured template, so the home card and client action cannot diverge.
- Offline reads use a versioned, user-isolated IndexedDB allowlist of shared studio query results; clear on identity changes and never persist tokens or authorize access beyond last-confirmed validity.
- PWA caching is generated by vite-plugin-pwa with one preview-safe registrar; navigations are network-first and APIs, OAuth, administration and payment responses are never cached.
- Studio client, service and monthly appointment screens share query definitions and invalidation keys to prevent incompatible shapes and duplicate requests.
